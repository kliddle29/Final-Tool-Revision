# Testing Scenario

## Chosen scenario

Download-and-install-to-first-use, start to finish: no scenario text
beyond "here's a link, try this out" and the download link itself. This
tests the real friction point directly (unzip, unsigned-app warning,
Screen Recording permission, then actually finding and using the
toggle) instead of a hypothetical situation.

Tester: my dad.

---

*The assignment's example scenarios ("about to open a distracting app",
"scrolling for a long time") are written for a behavior-interruption
tool. This tool explicitly isn't one -- the Tool Intent Statement's
Refusal Clause already ruled that framing out, same reframing the
Interface Ritual Sketch's Dignity Audit did. Pick one of these (or
write your own) and put it in your own words before the test.*

## Option A -- small text
"You're reading something on your screen with small text -- a label,
fine print, a chart with tiny axis numbers -- and it's hard to make out
clearly. You've heard about a tool that might help and have it
installed."

## Option B -- outside the browser
"You're used to browser zoom (Cmd+) working inside a browser tab, but
you're looking at something small in a different app -- a PDF viewer,
a spreadsheet, a system dialog -- where that shortcut doesn't apply.
Someone mentions a tool that might work anywhere on screen."

## Option C -- eyesight
"You have some difficulty reading small text on screen and normally
just lean in or squint. A friend installed a magnifier tool for you
and says to try it out."

Give the tester only the scenario text and the download link. Don't
explain the toggle hotkey, the tray icon, or how the lens follows the
cursor beforehand -- that's what the test is actually measuring.
